# 여행 플래너 (가칭)

일정, 예산, 지도 링크를 한곳에서 정리하는 반응형 웹 앱. 폰·태블릿·PC 브라우저에서 쓰고, 홈 화면에 추가하면 앱처럼 열려요(PWA).

## 지금 되는 것 (MVP)

**여행에 들어가면 그 여행 기간만큼의 캘린더가 먼저 보여요.** 1주 여행이면 1주, 2주 여행이면 2주만 나와요(달력처럼 일~토로 정렬하므로 기간 밖 칸은 비어 있어요). 날짜 칸에는 항공, 체크인·체크아웃, 일정 수(완료/전체)가 표시되고, 넓은 화면에서는 칸 안에 일정 이름도 보여요.

- 날짜를 누르면 **그날 일정으로 바로 이동**해요
- 캘린더 아래 버튼(항공·숙소·일정·준비·기본 정보)을 누르면 **세부 페이지**로 들어가요
- 아무것도 채우지 않은 새 여행에는 "항공권부터 등록하기" 안내가 보여요
- 세부 페이지에서는 위쪽 **5단계 탭**으로 바로 이동하고, 이전/다음 버튼으로 순서대로 채울 수도 있어요(비워 두고 건너뛰어도 돼요). "← 캘린더"로 돌아와요

1. **기본** 여행지, 기간, 총 예산. 항목별(항공·숙소·일정·쇼핑) 예산 내역
2. **항공** 왕복을 한 번에 입력하거나 편도를 직접 입력. 비용은 왕복 총액을 가는 편·오는 편에 반씩 나눠 기록
3. **숙소** 체크인·체크아웃, 박 수, 지도 링크. 어떤 숙소로도 덮이지 않는 밤이 있으면 알려줌
4. **일정** 일차별 일정. 등록한 항공·숙소를 꺼내 쓰는 장치가 모여 있어요
   - 항공·숙소 정보가 해당 날짜 맨 위에 자동으로 표시(출발·도착·체크인·체크아웃)
   - **후보지 보관함**: 가고 싶은 곳을 먼저 모아 두고, 날짜를 골라 일정에 넣기(넣으면 보관함에서 빠짐)
   - **불러오기 칩**: 일정을 추가·수정할 때 그날의 숙소와 공항을 눌러서 장소로 채우기
   - **일정 가능 시간대**: 항공 도착 1시간 뒤부터, 출발 2시간 전까지. 벗어난 시간의 일정과 같은 시간에 겹치는 일정은 경고
   - **경로 보기**: 그날 묵는 숙소에서 출발해 장소가 적힌(아직 안 한) 일정을 순서대로 잇는 구글지도 경로 링크. 숙소 복귀 포함 여부 선택
   - **하루씩 쭉 읽는 목록**: 일정은 한 줄로 줄이고 지도·순서·수정·삭제는 ⋯로 접어 둠. 날짜 머리글은 스크롤해도 고정, 위쪽 날짜 번호로 바로 이동, 후보지 보관함은 접어 둠
   - 이름만 적고 Enter로 빠르게 추가, 시간·장소·비용은 '자세히 추가'나 수정에서
   - 소화한 일정은 체크해서 완료 처리(취소선), 완료한 일정 숨기기, 완료 항목만 일괄 삭제
   - 순서 변경, 시간순 정렬, 장소별 네이버지도·구글지도 링크
5. **준비** 떠나기 전 챙길 것과 여행지에서 살 것
   - **준비물 체크리스트**: 자주 챙기는 것(서류, 전자기기, 생활, 옷)을 눌러서 추가하거나 직접 입력, 챙기면 체크
   - **쇼핑 목록**: 물건, 구매처, 예상 가격. 산 것은 체크하면 아래로 내려가고, 예상 가격은 예산에 합산

그 밖에
- 일정 텍스트 공유(지원 기기는 공유 시트, 아니면 클립보드 복사, 그것도 막히면 복사용 텍스트 표시)
- 백업 내보내기/불러오기(JSON). 불러오기 전에 덮어써도 되는지 확인
- 오프라인 동작(서비스 워커)
- 데이터는 **이 기기의 localStorage에만** 저장됩니다. 서버·계정·동기화는 아직 없어요.
- 이전 버전에서 저장한 데이터(항공·숙소·쇼핑 없음)도 그대로 열려요.

## 개발

```bash
npm install
npm run dev      # 개발 서버
npm test         # 단위 테스트 (날짜 계산, 달력 배치, 정렬, 예산 내역, 자동 일정, 빈 밤, 경로 링크, 일정 가능 시간대, 저장 데이터 호환)
npm run lint
npm run build    # dist/ 생성 (PWA 포함)
npm run preview  # 빌드 결과 미리보기
```

## 배포 (GitHub Pages)

**지금은 공개 배포를 하지 않아요.** `.github/workflows/deploy.yml`은 자동 실행을 꺼 두었고, 공개할 때만 Actions 탭에서 수동으로 실행하면 lint → 테스트 → 빌드 → 배포가 돌아요. 주소는 `https://<사용자>.github.io/NEW/`예요. 이 저장소가 공개 저장소라서 Pages를 켜면 누구나 접속할 수 있어요.

**공개할 때 처음 한 번만:** 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 바꿔 주세요. 이걸 켜기 전에는 배포 단계가 실패해요.

로컬에서 배포와 같은 조건으로 확인하려면 빌드와 미리보기 **둘 다**에 같은 경로를 지정해야 해요.

```bash
BASE_PATH=/NEW/ npm run build
BASE_PATH=/NEW/ npm run preview   # http://localhost:4173/NEW/
```

## 비공개 미리보기 (단일 파일)

파일 하나만 열 수 있는 곳(사이드 패널, Claude Artifact)용으로 앱을 HTML 한 파일에 합쳐요.

```bash
npm run build:single   # dist-single/index.html(전체 문서), dist-single/fragment.html(Artifact용)
```

이 버전은 서비스 워커를 쓰지 않아서 오프라인 설치(PWA)는 안 돼요. 또 이런 뷰어에서는 `confirm()`, 공유 시트, 파일 다운로드가 막혀 있어서, 삭제 확인은 앱 안의 버튼으로, 공유와 백업은 복사할 수 있는 텍스트로 대신 제공해요.

## 구조

- `src/lib/trip.ts` 날짜·예산·정렬·자동 일정 등 순수 로직 (테스트 대상)
- `src/lib/storage.ts` localStorage 읽기/쓰기와 데이터 검증
- `src/store.ts` 상태 훅, 해시 라우팅(`#/trip/<id>` 캘린더, `#/trip/<id>/<단계>`, `#/trip/<id>/plan/<날짜>`)
- `src/components/steps/` 단계별 화면(기본·항공·숙소·일정·준비)
- `src/components/` 캘린더(`TripCalendar`)와 개요(`TripOverview`), 공통 부품(단계 탭, 빠른 추가, 확인 버튼, 예산 요약, 폼)

## 알려진 한계

- PWA 아이콘이 SVG 하나뿐이라, 일부 기기의 홈 화면 아이콘이 기본 모양으로 나올 수 있어요. 배포 전에 192/512px PNG가 필요해요.
- 장소는 글자로만 저장해요. 좌표·장소 검색 자동완성은 없어요. 그래서 경로는 지도 앱이 장소 이름을 찾아 주는 데 기대고 있어요.
- 일정 가능 시간대의 여유 시간(도착 후 1시간, 출발 전 2시간)은 고정값이에요. 국내선·국제선 구분이나 개인별 조정은 아직 없어요.
- 경로 링크는 구글지도 기준이고, 경유지는 9곳까지만 반영돼요.
- 기기 간 동기화와 여러 명이 함께 편집하는 기능은 없어요.
