# 여행 플래너 — 제품 방향과 MVP (v1)

작성일: 2026-10-12 · 작성: Claude(모루) · 결정: 망치(당신)

`01-saas-idea-research.md`의 후보 5개 대신, 망치가 **여행 계획 플래너**로 방향을 정했습니다. 그리고 앱스토어용 네이티브 앱이 아니라 **반응형 웹**으로 가기로 했습니다.

## 1. 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 형태 | 반응형 웹 + PWA(홈 화면 추가) | 앱스토어 심사·수수료 없이 폰·태블릿·PC를 한 코드로. 링크 하나로 공유 가능 |
| 스택 | React + TypeScript + Vite | 가볍고 배포가 쉬움. 나중에 서버를 붙여도 그대로 확장 가능 |
| 데이터 | 우선 기기 내 localStorage | 계정·서버 없이 가장 빨리 써 보게 하려는 것. **동기화는 다음 단계** |
| 언어·지도 | 한국어 우선, 네이버/구글 지도 링크 | 한국어 사용자 기준의 가설. 아래 "검증 안 된 것" 참고 |

> 가정: 목표 시장을 아직 못 들었습니다. 한국어 사용자 기준으로 시작했고, 아니라면 알려 주세요.

## 2. 경쟁 현황 (2차 자료, 방향성만)

- **Wanderlog:** 지도 기반 계획과 그룹 협업이 강점. 무료는 장소 무제한과 실시간 협업, Pro(연 $39.99부터)에서 오프라인·경로 최적화·Gmail 자동 스캔.
- **TripIt:** 예약 확인 메일을 일정으로 바꿔 주는 것이 강점. Pro는 연 $49.
- **Stippl:** AI 일정 생성과 예산이 있고 프리미엄은 연 €24.99. 신생이라 초기 사용자의 동기화·충돌 불만이 있음.

**사용자 불만으로 반복해서 보인 것** (앱 리뷰 요약 사이트 기준, 유료 보고서가 섞여 있음):
- 일정이 길면 느려지고, 온보딩이 복잡하다
- 오프라인이 유료
- 월 단위 요금이 없고 연 결제만 있다
- 일정 순서 바꾸기와 예산 관리가 불편하다
- 계획한 뒤 길 찾기를 하려면 지도 앱에 다시 입력해야 한다

→ 시장은 이미 차 있습니다. **"여행 계획 앱이 없어서"가 아니라 "기존 앱이 불편해서"가 우리가 파고들 틈**입니다.

## 3. 우리의 차별화 가설 (아직 검증 전)

1. **가볍고 빠름:** 로그인 없이 바로 시작. 긴 일정에서도 느려지지 않기
2. **오프라인 무료:** 서비스 워커로 이미 동작함(브라우저에서 확인함)
3. **예산이 기본 기능:** 일정에 비용을 적으면 일차별·전체 합계와 초과 경고가 자동으로
4. **계획 → 이동 연결:** 장소별 지도 링크로 길 찾기까지 한 번에
5. **한국어·국내 지도 우선:** 네이버 지도 연동(현재는 검색 링크, 이후 장소 검색 API)

## 4. 지금 만든 것

`app/` 폴더. 실행 방법과 기능 목록은 `app/README.md` 참고.

**검증한 것**
- 단위 테스트 116개 통과 (날짜 계산, 윤일·월 경계, 달력 배치, 환율 해석, 가계부 계산, 나라 추측, 순서 변경, 시간순 정렬, 예산 내역, 항공·숙소 자동 일정, 숙소 빈 밤, 왕복 생성, 경로 링크, 일정 가능 시간대와 경고, 이전 저장 데이터 호환, 공유 텍스트)
- 린트, 타입 검사, 프로덕션 빌드 통과
- 실제 브라우저(390px 폰, 1280px PC)에서 새 여행 → 항공(왕복) → 숙소(빈 밤 경고) → 일정(자동 표시, 빠른 추가, 완료 체크) → 쇼핑 → 예산 합계 → 새로고침 후 같은 단계 유지, 가로 스크롤 없음, 콘솔 에러 없음
- 네트워크를 끈 상태에서 새로고침해도 앱이 열림

**검증하지 못한 것**
- 실제 폰(iOS Safari, 안드로이드 Chrome)에서의 동작과 홈 화면 설치. 데스크톱 Chromium에서만 확인함
- 공유 시트(`navigator.share`)는 데스크톱에서 클립보드 복사 경로만 확인함
- 접근성은 라벨과 포커스 표시를 신경 썼지만 스크린리더로는 확인 못 함
- 실제 사용자 반응. 아직 아무도 써 보지 않음

## 5. 다음 단계 제안

| 순서 | 할 일 | 이유 |
|---|---|---|
| 1 | **배포하고 지인 5~10명에게 써 보게 하기** (Cloudflare Pages나 Vercel, 무료) | 가설 1~5 중 무엇이 실제로 먹히는지 가장 싸게 확인 |
| 2 | PWA용 PNG 아이콘 만들기, 앱 이름·로고 정하기 | 배포 전 필수 |
| 3 | 계정 + 서버 동기화 + 공유 링크(그룹 여행) | 경쟁 앱 대비 필수 기능. 서버 선택(예: Supabase)이 필요한 결정 |
| 4 | 장소 검색 자동완성과 좌표(네이버/카카오 지도 API) | 계획 → 이동 연결을 제대로 구현 |
| 5 | AI 일정 초안 | 유료 기능 후보. 비용 구조를 먼저 계산해야 함 |

## 6. 수익 모델 (초안, 검증 필요)

- **무료:** 여행 계획 전부(오프라인 포함)
- **유료 후보:** 기기 간 동기화, 여러 명이 함께 편집, AI 일정 초안, 예약 메일 가져오기
- 경쟁사가 연 $24~49이고 "월 결제가 없다"는 불만이 있으니 **월 결제 옵션**을 차별점으로 삼는 것도 검증해 볼 만합니다.
- 숫자는 아직 없습니다. 1단계에서 사용자 반응을 본 뒤 정합니다.

## 7. 다른 앱 기능 조사와 반영 현황

등록한 항공·숙소를 일정 짤 때 꺼내 쓰는 장치와, 다른 앱에 있는 기능을 조사했습니다. 근거는 앱 소개 글과 스토어 설명 위주라서 **기능의 실제 깊이는 확인하지 못했습니다.**

| 조사에서 확인된 기능 | 어느 앱 | 이 앱의 반영 |
|---|---|---|
| 장소를 먼저 모아 두었다가 날짜로 옮겨 일정 만들기 | Wanderlog, 트리플(갈 곳만 고르면 동선까지) | **반영**: 후보지 보관함 → 날짜 선택 → 일정에 넣기 |
| 지도 기반 경로, 동선 | Wanderlog(경로 최적화는 유료), 트리플 | **일부 반영**: 숙소 기점 구글지도 경로 링크. 순서 최적화와 이동 시간 계산은 하지 않음 |
| 예약 확인 메일로 일정 자동 생성 | TripIt, Wanderlog | 보류: 메일 연동이나 AI 추출이 필요해서 서버가 있어야 함 |
| 준비물 리스트 | 여러 앱(Wanderlog은 범용형이라는 평이 있으나 확인 못 함) | **반영**: 자주 챙기는 것 칩 + 직접 입력 |
| 가계부·경비 정산 | 트리플, Wanderlog(출처마다 말이 엇갈림) | 보류: 실제 지출 기록, 환율, 동행자 정산 |
| 캘린더 연동 | TripIt | 보류: .ics 내보내기는 가능하나 일부 뷰어에서는 다운로드가 막힘 |
| AI 일정 생성 | 트리플 | 보류: 비용 구조를 먼저 계산해야 함 |
| 일정 이미지 저장, 동행자 초대 | 트리플 | 보류: 동행자 초대는 서버·계정 필요 |

**조사에서 나온 것이 아니라 우리가 만든 것** (경쟁 앱에 있는지 확인하지 못했습니다)
- 항공 도착·출발 시간으로 계산한 **일정 가능 시간대**와 경고. 여유 시간(도착 후 1시간, 출발 전 2시간)은 임의의 기본값입니다.
- 일정 추가 폼의 **불러오기 칩**(그날의 숙소·공항을 장소로 채우기)
- 숙소가 비는 **밤 알림**

## 8. 화면 구조 (캘린더 중심)

망치의 요청으로 정한 구조입니다: 여행에 들어가면 **그 여행 기간만의 캘린더**가 보이고, 거기서 세부 페이지로 들어갑니다.

```
여행 목록 ─ 여행 열기 ─▶ 캘린더(개요) ─ 날짜 누르기 ─▶ 일정(그 날짜로 스크롤)
                         │
                         └ 항공 / 숙소 / 일정 / 준비 / 기본 정보 버튼 ─▶ 세부 페이지(단계 탭 + 이전·다음)
```

- 캘린더는 1주면 1주, 2주면 2주만 보여줍니다. 날짜 칸에는 항공·체크인·체크아웃 점과 일정 수(완료/전체)가 보입니다.
- 일정 페이지는 하루씩 쭉 읽도록 한 줄 항목, 접히는 동작 버튼, 고정 날짜 머리글, 날짜 이동 줄로 정리했습니다.
- 새 여행은 캘린더가 먼저 보이고, 비어 있으면 "항공권부터 등록하기" 안내가 나옵니다.

**다음 후보:** 장소 검색 자동완성(좌표), 동행자별 정산, 실제 환율로 자동 받아오기 검증.

## 9. 여행 설정 고민과 가계부

망치가 "일정을 짤 때 어떤 설정이 있으면 좋을지 먼저 고민해 달라"고 해서, 여행을 만들 때 정할 것들을 따져 보고 정했습니다.

| 정할 것 | 일정 짤 때 쓰이는 곳 | 결정 |
|---|---|---|
| 나라 | 같은 이름의 장소 구분(일본·미국의 유니버설 스튜디오), 국내·해외 구분 | 반영 |
| 현지 통화·환율 | 가계부 자동 환산 | 반영 (나라에서 기본 통화를 추천) |
| 인원 수 | 1인당 비용 | 반영 |
| 국내·해외에 따른 준비물 | 국내는 여권·변환 어댑터가 필요 없음 | 반영 |
| 지도 링크 | 네이버지도는 해외 장소에 약함 | 해외 여행이면 구글지도만 표시 |
| 공유·물어보기용 글에 나라·통화 | 도우미에게 물어볼 때 맥락 전달 | 반영 |
| 취향·스타일 태그 | 지금 앱 안에서 쓸 곳이 없음 | 보류 (AI 일정 초안을 붙일 때) |
| 비자·전압·플러그 같은 나라별 정보 | 틀린 정보를 앱에 박아 넣을 위험 | 보류 (확인된 출처가 있어야 함) |
| 시차 | 항공 시각을 각 공항의 현지 시각으로 입력하면 이미 맞음 | 별도 설정 없음 |

**가계부 설계**
- 계획(항공·숙소·일정·쇼핑)과 실제 지출(가계부)을 분류별로 비교합니다.
- 외화 지출은 **기록하는 순간의 환율이 그 지출에 고정**됩니다. 이후 환율이 바뀌어도 이미 기록한 지출은 변하지 않습니다.
- 카드 청구 금액(원)을 아는 경우 그 금액으로 환율을 역산해 정확하게 기록합니다.
- 계획해 둔 비용을 지출로 한 번에 옮길 수 있습니다.
- 예전에 만든 여행은 여행지에 나라 이름이 들어 있으면(예: '대만') 그 나라로 추측하고, 아니면 국내로 봅니다.

**환율 자동 받아오기: 실제로 확인하지 못했습니다**
- 개발 환경의 네트워크 정책이 환율 서비스(`open.er-api.com`, `api.frankfurter.dev`, `api.frankfurter.app`)에 대한 접속을 막고 있어서, 실제 응답을 받아 보지 못했습니다.
- 응답 형식은 각 서비스의 문서를 기억하는 대로 썼고, 예상과 다른 응답은 모두 실패로 처리해 직접 입력으로 넘어가게 했습니다. 브라우저 시험에서 쓴 환율 응답은 "응답을 흉내 낸 것"으로, 앱이 응답을 처리하는 방식만 확인한 것입니다.
- 두 서비스를 차례로 시도합니다. open.er-api.com은 대만 달러·베트남 동까지 폭넓게 지원하고(무료 사용 시 출처 표기 필요), frankfurter는 유럽중앙은행 기준이라 일부 통화가 없습니다.
- 확인하려면 환경의 네트워크 설정에서 `open.er-api.com`을 허용하면 됩니다. 그러면 실제 응답으로 해석 코드를 검증할 수 있습니다.
- 비공개 미리보기(Artifact)는 외부 접속이 막혀 있어서 자동 환율이 동작하지 않고 직접 입력만 됩니다. 배포한 일반 웹 버전에서만 자동으로 받아와집니다.
