# 인수인계: 지금까지의 작업과 이어서 할 일

작성일: 2026-10-13 · 작성: Claude(모루) · 읽는 사람: 이어서 작업할 Claude 세션과 망치(사용자)

> 새 세션은 이 대화를 볼 수 없습니다. 이 문서와 저장소(`docs/01~03`, `app/README.md`)가 기억의 전부입니다. 먼저 이 문서를 끝까지 읽고 시작하세요.

## 1. 한 줄 요약

**여행 계획 반응형 웹앱(PWA)**을 만들었고, 기능 개발은 한 단락 안에 정리될 만큼 갖춰졌습니다. 이제 **무료 호스팅에 올려서 폰에 설치해 쓰는 단계**로 넘어가는 중이었고, 사용자가 호스팅 사이트에 로그인해서 같이 진행하려던 참에 이 세션에는 브라우저를 다루는 도구가 없어서 컴퓨터에서 이어서 하기로 했습니다.

## 2. 우리 사이의 약속과 사용자 성향

- 사용자는 한국어를 씁니다. **모든 대화와 문서는 한국어**로 합니다.
- 사용자는 스스로를 **망치**, Claude를 **모루**라고 부르며 "비즈니스 파트너로 사업을 같이 키우자"고 했습니다. 사용자가 방향을 정하고 Claude가 조사·설계·구현·검증을 맡습니다.
- 사용자는 큰 방향만 말하고 세부는 맡기는 편입니다. 요구가 모호해도 질문을 줄이고 합리적인 기본값으로 진행하되, **무엇으로 이해했는지 알려 주세요**(예: "'지우고'를 체크로 이해했는데 아니면 알려 주세요").
- **확인한 것과 확인하지 못한 것을 분명히 나눠서 보고**하는 것이 이 프로젝트의 규칙이 됐습니다. 시험하지 못한 것은 통과했다고 하지 않습니다.
- **자격 증명(비밀번호, 인증번호, 토큰)은 채팅에 받지 않습니다.** 로그인은 사용자가 직접 합니다.
- 사용자가 "우리 둘만 볼 수 있는 곳에서 먼저, 배포는 나중에"라고 했습니다. 공개 배포는 사용자 확인 없이 하지 않습니다.
- 사업(수익화)을 염두에 두고 있습니다. 호스팅은 **상업적 이용이 허용되는 곳**이어야 합니다.

## 3. 지금까지 한 일 (시간순)

1. SaaS 사업 아이디어 5개를 조사·비교했습니다 (`docs/01-saas-idea-research.md`). 사용자는 그중 고르지 않고 **여행 계획 플래너**로 방향을 정했습니다.
2. 반응형 웹 MVP를 만들었습니다 (Vite + React + TypeScript, 데이터는 기기 localStorage).
3. 단계별 계획(항공·숙소·일정·준비)과 일정 체크·쇼핑 목록을 추가했습니다.
4. 후보지 보관함, 불러오기 칩, 하루 경로 링크, 항공 기반 일정 가능 시간대, 준비물 체크리스트를 추가했습니다 (다른 여행 앱 조사 기반, `docs/02` 7절).
5. 여행에 들어가면 기간만큼의 **캘린더**가 먼저 보이고, 날짜를 누르면 그날 일정으로, 버튼으로 세부 페이지로 가도록 구조를 바꿨습니다. 일정 페이지는 하루씩 쭉 읽도록 정리했습니다.
6. **나라 선택**(같은 이름의 장소 구분), **가계부와 환율 환산**, 인원, 국내·해외에 따른 준비물 차이, "Claude에게 물어보기용 요약 복사"를 추가했습니다 (`docs/02` 9절).
7. **PWA 설치**를 갖췄습니다(아이콘, 설치 안내, 아이폰 안내, 오프라인).
8. 무료 호스팅을 조사했습니다 (`docs/03`). **Cloudflare Pages를 1순위로 권했고**, 사용자가 로그인해서 같이 올리려 했습니다.
9. 이 환경에는 브라우저 도구가 없어서 못 열었고, 사용자가 **자기 컴퓨터에서 이어서 하기로** 해서 이 문서를 만들었습니다.

## 4. 지금 앱이 하는 일

여행 목록 → 여행을 열면 **캘린더(개요)** → 날짜 누르면 일정, 버튼으로 세부 페이지. 세부 페이지는 6단계 탭입니다.

| 단계 | 내용 |
|---|---|
| 기본 | 나라, 도시·지역, 기간, 예산, 인원, 현지 통화. 항목별 예산 내역 |
| 항공 | 왕복 한 번에 입력 또는 편도 |
| 숙소 | 박 수, 지도 링크, 숙소가 비는 밤 알림 |
| 일정 | 항공·숙소 자동 표시, 후보지 보관함, 불러오기 칩, 일정 가능 시간대와 경고, 경로 링크, 완료 체크, 빠른 추가 |
| 준비 | 준비물 체크리스트(국내·해외 추천 다름), 쇼핑 목록 |
| 가계부 | 실제 지출, 환율 환산(기록 당시 환율 고정), 계획 대비, 분류별 표, 계획 비용 불러오기, 1인당 |

그 밖에 공유 텍스트, 백업 내보내기·불러오기, 오프라인, 앱 설치 안내.

## 9. 개발 방법

```bash
cd app
npm install
npm run dev        # 개발 서버
npm test           # 단위 테스트
npm run lint
npm run build      # dist/ (PWA 포함)
npm run e2e        # 브라우저 시험(Chromium 필요, app/e2e/README.md)
npm run build:single   # 파일 하나로 합친 비공개 미리보기용 (dist-single/)
```

- 구조는 `app/README.md`의 "구조"를 보세요. 계산 로직은 `src/lib/`(순수 함수 + 테스트), 화면은 `src/components/`.
- **데이터 형식을 바꿀 때**는 `src/lib/storage.ts`의 검증에 기본값을 넣어 **예전에 저장된 데이터가 그대로 열리게** 하세요(지금까지 지켜 온 규칙, 테스트가 있음).
- 새 기능에는 단위 테스트와 `e2e` 시나리오를 같이 추가하세요.

### 비공개 미리보기(Artifact)를 갱신하려면
`npm run build:single` → `dist-single/fragment.html`을 한 폴더에 복사 → Artifact 도구로 같은 URL에 발행. 이 뷰어에서는 `confirm()`, 공유 시트, 파일 다운로드, 서비스 워커, 외부 접속(환율)이 막혀 있어서 앱이 그걸 우회하도록 만들어져 있습니다(`VITE_EMBEDDED`).

## 10. 겪은 함정 (같은 실수를 반복하지 않도록)

- `vite preview`는 시작할 때 파일 목록을 기억합니다. 다시 빌드했으면 서버를 다시 띄우세요. 잘못된 서버는 JS 요청에 `index.html`을 200으로 돌려주므로 **상태 코드가 아니라 `content-type`을 확인**하세요.
- `pkill -f 패턴`은 명령줄에 그 패턴이 들어 있는 자기 셸까지 죽입니다. PID로 종료하세요.
- 시험이 실패할 때 앱이 깨진 건지 시험이 옛 동작을 기대하는 건지 먼저 가리세요(라벨 변경, 국내 여행에 여권 추천 없음 등 여러 번 있었습니다).
- 헤드리스 Chromium의 설치 가능성 검사는 시크릿 컨텍스트에서 `in-incognito` 오류를 냅니다. 영구 프로필로 검사하세요.
- 클라우드 컨테이너는 외부 접속이 막혀 있었습니다(환율 API, 일부 사이트). 로컬 컴퓨터에서는 아닐 수 있어서 위 7절의 확인을 거기서 할 수 있습니다.
- "지우고"는 **체크(완료 처리)**로 이해해서 구현했습니다(삭제도 함께 있음). 사용자가 다른 뜻이라고 하면 고치세요.
